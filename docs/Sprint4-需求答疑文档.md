## 💳 支付模块需求澄清

### Q1: 支付创建接口的请求参数和响应格式？

**A:**

**请求参数 (POST /api/payment/create)**
```json
{
  "orderId": "string",          // 必填，订单ID
  "paymentMethod": "string",    // 必填，支付方式: wechat/alipay/bankcard
  "amount": "string"           // 必填，支付金额(前端显示用，需后端校验)
}
```

**响应格式**
```json
{
  "code": 0,
  "message": "success",
  "data": {
    "paymentId": "string",       // 支付单号
    "orderId": "string",         // 订单ID
    "amount": "decimal",          // 支付金额
    "paymentMethod": "string",    // 支付方式
    "payUrl": "string",          // 第三方支付跳转URL(如需要)
    "qrCode": "string",          // 支付二维码(如适用)
    "expireTime": "datetime",    // 支付超时时间
    "status": "string"           // WAITING/EXPIRED
  }
}
```

### Q2: 支付回调接口的安全验证机制？

**A:**

**签名验证机制 (参考订单模块实现)**

```
签名算法: MD5(orderNo + amount + timestamp + secretKey)
```

**回调参数**
| 参数 | 说明 |
|------|------|
| orderNo | 订单号 |
| amount | 支付金额 |
| timestamp | 时间戳 |
| sign | 签名 |
| payChannel | 支付渠道 (wechat/alipay) |
| tradeNo | 第三方交易号 |

**注意事项**
- 使用 `PaymentSignatureUtils.verifyPaymentCallback()` 进行签名验证
- 金额需做二次校验，防止篡改
- 回调处理需保证幂等性

### Q3: 支付状态的枚举值？

**A:**

| 状态码 | 说明 | 触发条件 |
|--------|------|----------|
| `WAITING` | 待支付 | 创建支付单后 |
| `SUCCESS` | 支付成功 | 收到回调并验证通过 |
| `FAILED` | 支付失败 | 回调返回失败 |
| `EXPIRED` | 已过期 | 超过支付时限 |
| `REFUNDING` | 退款中 | 用户申请退款 |
| `REFUNDED` | 已退款 | 退款完成 |

### Q4: 支付时限如何确定？

**A:**

**业务规则 (参考业务规则文档)**

| 票品类型 | 支付时限 | 前端倒计时初始值 |
|----------|----------|------------------|
| 普通票 | 15分钟 | 900秒 |
| 热门票 | 5分钟 | 300秒 |
| 定制票 | 30分钟 | 1800秒 |

**前端如何获取时限**
- 方案A: 创建订单时后端返回 `payDeadline` 字段，前端计算剩余时间
- 方案B: 后端提供 `GET /api/ticket/{id}/payment-timeout` 接口

### Q5: 支付页面的金额从哪里获取？

**A:**

**正确流程**

1. 用户从结算页 (CheckoutScreen) 点击"去支付"
2. 前端调用 `POST /api/orders` 创建订单，获取订单信息
3. 跳转至支付页面 (PaymentScreen)，传入 `orderId`
4. 支付页面通过 `GET /api/orders/{orderId}` 获取订单详情中的 `totalAmount`
5. 用户选择支付方式后，调用 `POST /api/payment/create` 创建支付单

**前端已有逻辑**

```json
    "username": "string",
    "phone": "string",

    "nickname": "string",

    "gender": "number",          // 0-未知, 1-男, 2-女
    "birthday": "string",         // YYYY-MM-DD
```

| 数据库值 | 前端类型 | 显示文案 |
|----------|----------|----------|
| 0 | unknown | 未知 |

| 2 | female | 女 |

### Q7: 更新用户资料的字段限制？

**A:**

**PUT /api/user/profile 请求参数**

```json
{
  "nickname": "string",      // 可选，1-20字符
  "avatar": "string",        // 可选，头像URL
  "email": "string",         // 可选，邮箱格式校验
  "gender": "number",        // 可选，0/1/2
  "birthday": "string"       // 可选，YYYY-MM-DD格式
}
```

**不可修改的字段**
- userId / username - 用户标识
- phone - 手机号(需单独验证流程)
- userType / userLevel - 系统设置
- points / totalOrderAmount - 系统计算
