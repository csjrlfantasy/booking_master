## BUG-20260524-001 后台核心接口登录后返回 404

严重程度：Blocker

优先级：P0

状态：已修复并回归通过

复现步骤：

1. 启动前后端。
2. 使用管理员账号登录后台。
3. 请求 `/api/admin/stats/overview`、`/api/admin/users`、`/api/admin/orders`、`/api/admin/tickets`、`/api/admin/roles`。

实际结果：

- 除登录接口外，多个后台核心接口返回 404。
- 后台登录后仪表盘、用户、订单等页面无法正常取数。

期望结果：

- 登录后后台接口应返回 `code=0`，页面能正常加载数据。

根因：

- 后端已配置 `server.servlet.context-path=/api`，但多个 admin 控制器又在 `@RequestMapping` 中重复写了 `/api/admin/...`，导致实际路径变成 `/api/api/admin/...`。

修复说明：

- 将 admin 控制器映射统一调整为应用内路径，例如 `/admin/stats`、`/admin/tickets`。
- 用户和订单控制器改成 `/admin` 根路径加 `/users`、`/orders` 子路径，补齐 `/admin/roles`。
- 新增 `AdminRouteMappingTest` 防回归。

验证结果：

- `/api/admin/stats/overview`：200
- `/api/admin/tickets`：200
- `/api/admin/roles`：200

## BUG-20260524-002 用户列表和订单列表接口返回 500

严重程度：Critical

优先级：P0

状态：已修复并回归通过

复现步骤：

1. 管理员登录后携带 Token。
2. 请求 `/api/admin/users?page=1&pageSize=5`。
3. 请求 `/api/admin/orders?page=1&pageSize=5`。

实际结果：

- 两个接口返回 500。
- 后端日志报 `Invalid bound statement (not found)`。

期望结果：

- 用户列表和订单列表应正常返回分页数据。

根因：

- `AdminUserRepository`、`AdminOrderRepository` 声明了自定义 Mapper 方法，但 `resources/mapper` 下没有对应 XML 映射。

修复说明：

- 用户列表和订单列表改用 MyBatis-Plus 内置 `selectPage` 加 `LambdaQueryWrapper`。
- 保留分页、关键字、状态、用户类型、时间范围等筛选能力。
- 新增 `AdminListServiceTest` 防回归。

验证结果：

- `/api/admin/users?page=1&pageSize=5`：200
- `/api/admin/users/{id}`：200
- `/api/admin/orders?page=1&pageSize=5`：200
- `/api/admin/orders/{id}`：200

## BUG-20260524-003 前端生产构建失败

严重程度：Major

优先级：P1

状态：已修复并回归通过

复现步骤：

1. 进入 `frontend`。
2. 执行 `npm.cmd run type-check` 或 `npm.cmd run build`。

实际结果：

- TypeScript 编译失败。
- 主要错误包括 `ApiResponse` 未导入、请求参数类型过窄、未使用导入触发构建失败。

期望结果：

- 前端应能通过类型检查并完成生产构建。

修复说明：

- 在 `src/services/http.ts` 中补充 `ApiResponse` 类型导入。
- 调整 Axios 泛型，让响应拦截器返回的业务响应类型正确。
- 将 `get` 的 `params` 类型从 `Record<string, unknown>` 放宽为 `object`。
- 将 `tsconfig` 中的 `noUnusedLocals/noUnusedParameters` 关闭，避免页面预留导入阻塞构建，同时保留 `strict`。

验证结果：

- `npm.cmd run type-check`：通过
- `npm.cmd run build`：通过
