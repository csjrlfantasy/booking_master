## 三、每日站会议程

### 固定议程 (每日 10:00)
```
1. 各Agent进度汇报 (5分钟)
   - 昨日完成
   - 今日计划
   - 阻塞问题

2. 问题升级 (5分钟)
   - 需要PM协调的问题
   - 风险预警

3. 任务状态更新 (5分钟)
   - 更新任务看板
   - 确认依赖关系
```

### 汇报模板

**后端汇报**:
```
- 昨日完成: [完成的API/功能]
- 今日计划: [计划开发的API/功能]
- 遇到问题: [阻塞问题，如无则填"无"]
- 接口文档: [是否已更新Swagger]
```

**前端汇报**:
```
- 昨日完成: [完成的页面/组件]
- 今日计划: [计划开发的页面/组件]
- 遇到问题: [阻塞问题，如无则填"无"]
- API对接: [对接的API名称]
```

**QA汇报**:
```
- 昨日完成: [执行的测试用例数]
- 今日计划: [计划执行的测试用例]
- 发现Bug: [新发现的Bug数量]
- 测试覆盖率: [当前覆盖率]
```

## 四、风险监控

### 每日风险检查

| 风险项 | 检查频率 | 监控指标 | 预警阈值 |
|--------|----------|----------|----------|
| 开发进度 | 每日 | 任务完成率 | <80% |
| 测试进度 | 每日 | 用例执行率 | <70% |
| Bug数量 | 每日 | 新增Bug数 | >5/天 |
| 代码质量 | 每2天 | 评审通过率 | <90% |

### 风险升级机制

```
Level 1: 团队内解决 (Agent自行处理)
Level 2: PM协调 (影响单个任务)
Level 3: 管理层介入 (影响整个Sprint)
```
