## 1. 用户模块

### 1.1 功能概述

用户模块是平台的基础模块，提供用户注册、登录、个人信息管理、密码修改、账户余额管理等功能。用户分为普通用户、VIP用户和企业用户三种类型。

### 1.2 功能需求

#### FR-USER-001 用户注册

| 属性 | 说明 |
|------|------|
| 接口 | `POST /api/user/register` |
| 认证 | 无需登录 |
| 请求参数 | username(必填), password(必填), phone(必填, 格式:1[3-9]xxxxxxxxx), email(选填), nickname(选填), source(选填: app/h5/miniapp), inviterId(选填) |
| 业务规则 | BR-USER-001~006 |
| 成功返回 | code=0, data=用户ID |

**业务规则：**
- BR-USER-001: 用户名必须唯一，已存在返回 100106
- BR-USER-002: 手机号必须唯一，已注册返回 100104
- BR-USER-003: 邮箱如填写则必须唯一，重复返回 100105
- BR-USER-004: 密码需加密存储（BCrypt）
- BR-USER-005: 注册来源记录到 source 字段
- BR-USER-006: 新用户默认状态为"正常"(status=1)

#### FR-USER-002 用户登录

| 属性 | 说明 |
|------|------|
| 接口 | `POST /api/user/login` |
| 认证 | 无需登录 |
| 请求参数 | username(必填), password(必填) |
| 业务规则 | BR-USER-007~011 |
| 成功返回 | code=0, data={userId, username, nickname, phone, email, token, expiresIn} |

**业务规则：**
- BR-USER-007: 连续登录失败达到上限后锁定账户30分钟（100110）
- BR-USER-008: 账户被禁用时无法登录（100102）
- BR-USER-009: 登录成功返回JWT Token，有效期24小时
- BR-USER-010: 登录成功更新最后登录时间和IP
- BR-USER-011: 登录成功后重置登录失败计数

#### FR-USER-003 获取用户信息

| 接口 | `GET /api/user/{userId}` |
|------|------|
| 认证 | 需要登录 |
| 安全规则 | 用户只能查看自己的信息 |

#### FR-USER-004 根据用户名获取用户

| 接口 | `GET /api/user/username/{username}` |
|------|------|
| 认证 | 需要登录 |

#### FR-USER-005 修改个人资料

| 接口 | `PUT /api/user/profile` |
|------|------|
| 认证 | 需要登录 |
| 可修改字段 | nickname(1-50字符), phone(格式校验), email(格式校验), gender(0/1/2), birthday, avatar |

#### FR-USER-006 修改密码

| 接口 | `PUT /api/user/password` |
|------|------|
| 认证 | 需要登录 |
| 请求参数 | oldPassword(必填), newPassword(必填, 6-20字符), confirmPassword(必填) |
| 业务规则 | newPassword与confirmPassword必须一致；旧密码必须正确 |

#### FR-USER-007 退出登录

| 接口 | `POST /api/user/logout` |
|------|------|
| 认证 | 需要登录 |

### 1.3 用户状态定义

| 状态码 | 含义 |
|--------|------|
| 0 | 禁用 |
| 1 | 正常 |
| 2 | 待审核 |

### 1.4 用户类型

| 类型码 | 含义 |
|--------|------|
| 1 | 普通用户 |
| 2 | VIP用户 |
| 3 | 企业用户 |

## 2. 票务模块

### 2.1 功能概述

票务模块是平台的核心模块，提供演出/赛事/展览票品的展示、搜索、筛选、详情查看等功能。支持多种票档价格、场次管理、秒杀活动、用户评论和开售提醒。

### 2.2 功能需求

#### FR-TICKET-001 票品列表查询

| 接口 | `GET /api/tickets` |
|------|------|
| 认证 | 无需登录 |
| 请求参数 | categoryId, keyword, startDate, endDate, minPrice, maxPrice, sortBy(saleCount/price/createTime), sortOrder(asc/desc), pageNum, pageSize |
| 返回 | PageResult（分页票品列表） |

**业务规则：**
- BR-TICKET-001: 默认按 sortOrder 升序排列
- BR-TICKET-002: 只返回状态为"在售"(status=2)的票品

#### FR-TICKET-002 票品详情

| 接口 | `GET /api/tickets/{id}` |
|------|------|
| 认证 | 无需登录 |
| 返回 | 票品完整信息（含场次、价格档位、座位图） |

#### FR-TICKET-003 票品搜索

| 接口 | `GET /api/tickets/search` |
|------|------|
| 参数 | keyword(关键词), minPrice, maxPrice, startDate, endDate, sortBy, sortOrder, pageNum, pageSize |

#### FR-TICKET-004 热门推荐

| 接口 | `GET /api/tickets/hot` |
|------|------|
| 参数 | limit(默认10) |
| 规则 | 返回 isHot=1 且 status=2 的票品 |

#### FR-TICKET-005 即将开售

| 接口 | `GET /api/tickets/upcoming` |
|------|------|
| 参数 | limit(默认10) |
| 规则 | 返回 status=1(待售) 且 bookStartTime 最近的票品 |

#### FR-TICKET-006 票品分类

| 接口 | `GET /api/categories` |
|------|------|
| 返回 | 全部分类列表，附带各分类下的票品数量 |

#### FR-TICKET-007 秒杀活动

| 接口 | `GET /api/tickets/flash-sale` |
|------|------|
| 参数 | limit(默认10) |
| 规则 | 返回当前时间在 startTime~endTime 内且 status=1 的秒杀票品 |

#### FR-TICKET-008 用户评论

| 接口 | `GET/POST /api/tickets/{ticketId}/comments` |
|------|------|
| 查看 | 无需登录，返回评论摘要（平均评分、总数）和评论列表（默认10条，最多50条） |
| 发表 | 需要登录，参数 rating(1-5), content |

#### FR-TICKET-009 开售提醒

| 接口 | `GET/POST /api/tickets/{ticketId}/reminders` |
|------|------|
| 规则 | 仅 status=1(待售) 的票品可设置提醒；可查询当前用户是否已设置 |

### 2.3 票品状态定义

| 状态码 | 含义 |
|--------|------|
| 0 | 下架 |
| 1 | 待售 |
| 2 | 在售 |
| 3 | 售罄 |
| 4 | 已结束 |

### 2.4 票品数据模型

票品(Ticket)包含：名称、副标题、分类、场馆、海报图、描述、亮点、注意事项、演出时间类型(单场/区间)、演出日期、时长、年龄限制、艺人信息、最低/最高价、总库存/可用库存、每人限购数、开售/结束时间、是否热门/推荐、状态、浏览量、销量、排序权重、标签。

每个票品可有多个**价格档位**(TicketPriceLevel)：如VIP区/普通区，含价格、库存、座位类型(对号/自由/站票)。

每个票品可有多个**场次**(TicketSession)：含场次编号、演出日期、开始/结束时间、容量。

| 返回 | 购物车列表（含票品名、海报、场次、价格档位、数量、小计） |

| 接口 | `GET /api/cart/count` |

| 接口 | `PUT /api/cart/quantity` |

## 4. 订单模块

### 4.1 功能概述

订单模块管理用户从下单到完成的全流程。支持订单创建、列表查询、详情查看、取消订单、确认完成、支付回调等操作。

### 4.2 订单状态机

```
                    ┌──────────────┐
                    │ PENDING_PAY  │ (1.待支付)
                    │  (待支付)     │
                    └──────┬───────┘
                           │
              ┌────────────┼────────────┐
              │ 支付成功    │ 超时/取消   │
              ▼            │            ▼
        ┌──────────┐      │     ┌──────────┐
        │   PAID   │(2)   │     │CANCELLED │(4)
        │  已支付   │      │     │  已取消   │
        └────┬─────┘      │     └──────────┘
             │             │
             │ 申请退款     │
             ▼             │
        ┌──────────┐      │
        │REFUNDING │(6)   │
        │  退款中   │      │
        └────┬─────┘      │
             │             │
        ┌────┴────┐       │
        │ 退款成功  │       │
        ▼          ▼       │
   ┌─────────┐           │
   │REFUNDED │(5)        │
   │  已退款  │           │
   └─────────┘           │
                          │
              ┌───────────┘
              │ 确认完成
              ▼
        ┌──────────┐
        │COMPLETED │(3)
        │  已完成   │
        └──────────┘
```

### 4.3 功能需求

#### FR-ORDER-001 创建订单

| 接口 | `POST /api/orders` |
|------|------|
| 认证 | 需要登录 |
| 请求参数 | ticketId(必填), sessionId(必填), items(必填, 订单项列表), contactName(必填), contactPhone(必填), contactIdCard(选填), couponId(选填), userRemark(选填), source(选填) |
| 业务规则 | BR-ORDER-001~008 |

**业务规则：**
- BR-ORDER-001: 每人每单限购10张
- BR-ORDER-002: 每人每天限购20张
- BR-ORDER-003: 每人每月限购50张
- BR-ORDER-004: 实名制票品每身份证限购1张
- BR-ORDER-005: 库存扣减使用乐观锁防超卖（版本号重试最多3次）
- BR-ORDER-006: 订单创建后状态为PENDING_PAY
- BR-ORDER-007: 支付超时时间：普通票15分钟、热门票5分钟、自定义30分钟
- BR-ORDER-008: 订单金额 = 票单价×数量 - 优惠券抵扣 - 积分抵扣

#### FR-ORDER-002 订单列表

| 接口 | `GET /api/orders` |
|------|------|
| 参数 | status(1-6, 选填), page, pageSize |
| 返回 | PageResult，按创建时间倒序 |

#### FR-ORDER-003 订单详情

| 接口 | `GET /api/orders/{id}` |
|------|------|
| 说明 | 支持订单ID或订单号查询 |

#### FR-ORDER-004 取消订单

| 接口 | `PUT /api/orders/{id}/cancel` |
|------|------|
| 规则 | 仅PENDING_PAY状态可取消；取消后恢复库存和优惠券 |

#### FR-ORDER-005 确认完成

| 接口 | `PUT /api/orders/{id}/complete` |
|------|------|
| 规则 | 仅已支付订单可确认完成 |

#### FR-ORDER-006 支付回调

| 接口 | `POST /api/orders/pay/callback` |
|------|------|
| 认证 | 签名验证（无需登录Token） |
| 参数 | orderNo, amount, timestamp, sign, payChannel, tradeNo |
| 规则 | 使用PaymentSignatureUtils验证签名；回调成功后更新订单状态为PAID |

### 4.4 订单数据模型

订单(Order)包含：订单号(ORD+日期+序列)、用户ID、票品信息、场次信息、场馆信息、数量/金额/实付金额、优惠券抵扣、积分抵扣、订单状态、支付状态、支付渠道、交易号、联系人信息、取消/完成时间、过期时间。

## 5. 支付模块

### 5.1 功能概述

支付模块处理用户的支付请求、支付状态查询、退款申请。支持支付宝、微信支付、银行卡、银联支付（当前为Mock模拟）。

### 5.2 功能需求

#### FR-PAY-001 创建支付

| 接口 | `POST /api/payment/create` |
|------|------|
| 认证 | 需要登录 |
| 参数 | orderNo(必填), amount(必填), payChannel(必填: alipay/wechat/bank/unionpay), clientIp(选填), returnUrl(选填), paymentScene(默认H5) |
| 规则 | 订单必须为PENDING_PAY状态；金额必须与订单payAmount一致 |

#### FR-PAY-002 Mock支付

| 接口 | `POST /api/payment/mock-pay` |
|------|------|
| 说明 | 模拟第三方支付的测试接口 |

#### FR-PAY-003 支付状态查询

| 接口 | `GET /api/payment/status/{orderNo}` |

#### FR-PAY-004 申请退款

| 接口 | `POST /api/payment/refund` |
|------|------|
| 参数 | orderNo(必填), reason(选填), refundAmount(选填), proofImages(选填) |
| 退款规则 | BR-REFUND-001~005 |

**退款规则：**
- BR-REFUND-001: 演出前 >=7天 → 退100%
- BR-REFUND-002: 演出前 3-7天 → 退70%
- BR-REFUND-003: 演出前 1-3天 → 退50%
- BR-REFUND-004: 演出前 <1天 → 不可退
- BR-REFUND-005: 演出已开始/已结束 → 不可退
- BR-REFUND-006: 每订单仅允许一次退款申请
- BR-REFUND-007: 优惠券不退还（按比例分摊到各票品）

#### FR-PAY-005 退款状态查询

| 接口 | `GET /api/payment/refund/{orderNo}` |

#### FR-PAY-006 取消支付

| 接口 | `DELETE /api/payment/{orderNo}` |
|------|------|
| 规则 | 仅可取消待支付状态的支付记录 |

#### FR-PAY-007 支付网关回调

| 接口 | `POST /api/payment/callback` |
|------|------|
| 认证 | 签名验证 |
| 参数 | orderNo, amount, timestamp, sign, payChannel, tradeNo |
| 规则 | 签名验证失败返回100405；成功则更新支付和订单状态 |

### 5.3 支付状态定义

| 状态 | 含义 |
|------|------|
| PENDING | 待支付 |
| SUCCESS | 支付成功 |
| FAILED | 支付失败 |
| CLOSED | 已关闭 |

### 5.4 退款状态定义

| 状态 | 含义 |
|------|------|
| APPLYING | 申请中 |
| PROCESSING | 处理中 |
| SUCCESS | 退款成功 |
| FAILED | 退款失败 |
| REJECTED | 已拒绝 |

## 6. 优惠券模块

### 6.1 功能概述

优惠券模块提供优惠券的领取、查看、使用、核销功能。支持满减券、折扣券、立减券和品类券，单笔订单最多使用1张优惠券。

### 6.2 功能需求

#### FR-COUPON-001 获取可用优惠券

| 接口 | `GET /api/coupons` |
|------|------|
| 认证 | 需要登录 |
| 参数 | orderAmount(金额), ticketId, categoryId |
| 规则 | 根据订单金额和票品信息筛选可用优惠券 |

#### FR-COUPON-002 我的优惠券列表

| 接口 | `GET /api/coupons/list` |
|------|------|
| 参数 | status(0-未使用/1-已使用/2-已过期/3-已禁用), page, pageSize |

#### FR-COUPON-003 领取优惠券

| 接口 | `POST /api/coupons/receive` |
|------|------|
| 参数 | couponId(必填) |
| 规则 | 每人限领数量限制；库存不足时无法领取 |

#### FR-COUPON-004 使用优惠券

| 接口 | `POST /api/coupons/use` |
|------|------|
| 参数 | userCouponId(必填), orderId |
| 规则 | 优惠券必须在有效期内；订单金额需满足最低消费；一单只能用一张券 |

#### FR-COUPON-005 核销验证

| 接口 | `POST /api/coupons/validate` |
|------|------|
| 参数 | couponCode(必填), orderAmount(必填), ticketId, categoryId |
| 返回 | 是否可用、优惠金额、不可用原因 |

#### FR-COUPON-006 优惠券详情

| 接口 | `GET /api/coupons/{id}` |

### 6.3 优惠券类型

| 类型码 | 名称 | 说明 |
|--------|------|------|
| 1 | 满减券 | 满X元减Y元 |
| 2 | 折扣券 | 打X折，可设最大优惠金额 |
| 3 | 立减券 | 直接减X元 |

### 6.4 优惠券状态

| 状态码 | 含义 |
|--------|------|
| 0 | 未使用 |
| 1 | 已使用 |
| 2 | 已过期 |
| 3 | 已禁用 |

### 6.5 核心业务规则

- BR-COUPON-001: 每笔订单最多使用1张优惠券
- BR-COUPON-002: 优惠券与促销活动不可叠加（自动选最优）
- BR-COUPON-003: 订单取消时自动退还优惠券
- BR-COUPON-004: 过期优惠券自动失效

后台管理系统为运营人员提供用户管理、订单管理、票品管理、Banner管理、秒杀管理、数据统计、系统配置等功能。
