# 票多星票务平台下一阶段功能规划设计

## 背景

票多星当前定位为综合票务平台，已有 Web 客户端、后台管理端、Spring Boot 后端和 React Native Android 端雏形。后续规划只聚焦票务平台本身，不纳入 AI 测试智能体能力；AI 测试平台由独立项目维护。

本阶段目标是把票多星从“功能演示系统”推进到“业务闭环完整、数据一致、可教学测试”的票务平台。

## 设计原则

- 客户端优先保证购票闭环完整：能浏览、能下单、能支付、能查订单、能退票。
- 后台优先保证运营闭环完整：能配置票务、库存、价格、活动、Banner、退款和用户余额。
- Web 与 Android 共用后端真实接口，Android 不再长期依赖 Mock 数据。
- 所有金额、库存、订单状态、退款状态和统计数据都以后端真实数据为准。
- 防黄牛能力要围绕口号“票多星，不卖黄牛票”展开，先做规则可见、可测、可运营的轻量版本。
- 平台保留测试友好能力，例如演示数据、测试账号、一键重置数据和关键流程自动化测试。

## 一期范围：Web 客户端购票闭环

### 客户端首页

- 首页展示可运营 Banner，支持 Web/App 平台区分。
- 分类入口控制在短标签内，避免移动端换行。
- 首页包含“即将开售”“秒杀特价票”“抢票播报站”“必看演出”等模块。
- 点击票务卡片进入票务详情页，不在首页右侧固定展示购买面板。

### 票务详情

- 展示票务名称、海报、类型、地点、开演时间、价格区间、状态、长描述和购票须知。
- 海报固定比例展示，详情文案很长时不得拉伸图片。
- 支持场次选择、区域/票档选择，不同区域价格和库存独立。
- 支持“售卖中”“即将开售”“已下架”“已售罄”等状态。
- 评论只出现在具体票务详情页，评论与票务绑定。
- 即将开售票务显示“提醒我”，开售票务显示“立即购买”。

### 下单与支付

- 用户选择场次、票档、数量后提交订单。
- 创建订单后进入待支付状态，生成 15 分钟支付倒计时。
- 15 分钟未支付的订单自动取消，并释放库存。
- 支付方式使用 Mock 微信/支付宝余额支付。
- 用户表保留微信余额和支付宝余额字段，支付成功时直接扣减对应余额。
- 余额不足时支付失败，订单继续保持待支付直到超时或用户取消。

### 订单查询与退款

- 客户端提供个人订单查询，支持全部、待支付、已支付、已取消、退款中、已退款筛选。
- 订单详情展示联系人、联系电话、备注、票务名称、场次、票档、数量、金额、支付方式和订单状态。
- 待支付订单支持取消。
- 已支付订单支持客户申请退票。
- 客户退票规则以最近确认规则为准：
  - 开演前 24 小时内退票，扣除 75% 手续费。
  - 开演前 48 小时内退票，扣除 50% 手续费。
  - 开演前 7 天内退票，扣除 75% 手续费。
  - 其他时间全额退款。
- 管理端强制退票固定全额退款，不套用客户手续费规则。

## 二期范围：后台运营闭环

### 票务管理

- 票务列表显示演出名称，不以地点作为主标题。
- 票务列表展示分类、价格区间、库存、状态、开售类型和创建时间。
- 支持按关键词、分类、状态、开售类型筛选。
- 支持创建、编辑、上架、下架、删除或软删除。
- 创建/编辑票务支持上传海报图片，并在客户端真实展示。
- 支持预售/马上出售设置。
- 支持多场次、多区域、多票档价格与库存。

### 批量操作

- 票务管理支持批量上架、批量下架、批量删除。
- 订单管理支持批量取消、批量强制退款、批量导出。
- 用户管理支持批量启用、禁用、充值或导出。
- 批量操作必须有二次确认，并返回成功/失败明细。

### 活动与首页配置

- Banner 管理支持平台、排序、上下线时间、跳转类型和跳转目标。
- 秒杀特价票作为独立运营活动，支持活动价、活动库存、开始/结束时间和状态。
- 抢票播报站只展示秒杀/抢票类活动，不混用普通热门票。
- 首页模块可以通过后台控制显示顺序和展示数量。

### 用户与余额

- 后台用户列表支持关键词、状态、用户类型筛选。
- 用户消费金额按真实订单统计，不使用假数据。
- 后台可给用户微信余额或支付宝余额充值。
- 充值记录应保留操作人、渠道、金额、时间和备注。

### 数据统计

- 数据统计必须来自真实订单、支付、退款和票务库存数据。
- 首页统计展示今日订单、今日销售额、待退款数、库存告警、热门票务。
- 票务统计展示浏览、下单、支付、退款、剩余库存和售罄率。

## 三期范围：Android 端真实闭环

Android 端保留现有 React Native 架构，但逐步替换 Mock 数据。

- 首页 Banner 接真实 `/banners?platform=app`。
- 分类、票务列表、票务详情接真实票务 API。
- 立即购买、提醒我、评论、订单列表、订单详情、支付和退款接真实 API。
- 底部 Tab 的首页、分类、订单、我的都必须可用。
- Profile、退款申请、优惠券、收藏等占位页要么实现，要么从入口暂时隐藏。
- Android 与 Web 使用一致的订单状态、支付状态和退款规则。

## 四期范围：防黄牛能力

### 轻量规则

- 同一用户对同一票务可配置限购数量。
- 同一手机号对同一票务可配置限购数量。
- 秒杀活动可配置单用户限购数量。
- 高频下单、频繁取消、余额异常支付失败可标记为风险行为。

### 后台运营

- 后台新增风险订单列表。
- 管理员可以查看风险原因、用户信息、订单信息和操作记录。
- 管理员可以手动加入或移出黑名单。
- 黑名单用户禁止下单，但允许查看历史订单和申请退款。

## 五期范围：测试友好能力

- 提供测试账号清单，包括普通客户、余额不足客户、管理员、禁用用户。
- 提供演示票务数据，包括售卖中、即将开售、已下架、已售罄、秒杀票。
- 提供一键重置测试数据脚本。
- 自动化测试覆盖：
  - 登录与权限隔离。
  - 客户端购票闭环。
  - 订单 15 分钟超时取消。
  - 微信/支付宝余额扣减。
  - 客户退票手续费规则。
  - 管理端强制全额退款。
  - 票务上下架与筛选。
  - Banner 与秒杀配置。
  - Android 关键页面 API 联调。

## 不纳入范围

- 不在票多星项目中集成 AI 测试智能体。
- 不接入真实微信、支付宝支付网关。
- 不开发真实短信、App 推送或实名身份核验。
- 不实现复杂座位图选座，当前以区域/票档为主。
- 不做真实黄牛识别模型，先做规则型风控。

## 推荐实施顺序

1. Web 客户端购票闭环修整：详情页、下单、支付、订单查询、退款。
2. 后台票务运营增强：票务状态、区域票档、图片上传、筛选、批量操作。
3. 后台首页运营增强：Banner、秒杀、抢票播报站、首页模块配置。
4. 数据一致性和统计真实化：余额、库存、消费金额、退款金额、统计页。
5. Android 端真实 API 联调：先首页/详情/订单，再支付/退款/个人中心。
6. 防黄牛一期：限购、风险订单、黑名单。
7. 测试友好能力：测试数据重置、自动化测试和演示账号。

## 验收标准

- 客户端普通用户可以从首页进入票务详情，并完成下单、支付、订单查询和退款申请。
- 后台管理员可以创建票务、上传图片、配置票档、上架下架、配置 Banner 和秒杀活动。
- 订单、库存、余额、退款和统计数据在客户端与后台保持一致。
- 订单联系人信息在客户订单详情和后台订单详情都能看到。
- Android 底部 Tab 入口可用，核心页面不再只依赖 Mock。
- 自动化测试能覆盖核心购票链路和高风险规则。
