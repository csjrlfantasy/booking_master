# 身份证购票校验设计

## 目标

为票多星增加实名观演人能力：客户可在个人主页维护常用观演人身份证，购票时按票数选择对应观演人；后端按中国大陆 18 位居民身份证计算年龄，并校验票务年龄限制。

## 业务规则

- 身份证只支持中国大陆 18 位居民身份证。
- 校验内容包括：长度、前 17 位数字、第 18 位数字或 X、出生日期合法、校验位正确。
- 票务年龄限制使用现有 `ticket.age_limit` 字段，规范为 `0+`、`6+`、`12+`、`16+`、`18+` 等最小年龄。
- 每 1 张票必须绑定 1 个观演人证件。购买 3 张票时必须提交 3 个观演人。
- 同一笔订单内不允许重复使用同一个身份证号。
- 任一观演人未达到票务年龄限制时，下单失败。
- 订单明细需要保存观演人姓名和身份证号，展示时默认脱敏。

## 后端设计

- 新增 `user_identity` 表，保存用户常用观演人：
  - `id`
  - `user_id`
  - `real_name`
  - `id_card_no`
  - `phone`
  - `is_self`
  - `is_default`
  - `created_at`
  - `updated_at`
  - `deleted_at`
- 新增客户证件接口：
  - `GET /api/user/identities`
  - `POST /api/user/identities`
  - `PUT /api/user/identities/{id}`
  - `DELETE /api/user/identities/{id}`
- `CreateOrderRequest.OrderItemRequest` 增加 `attendees` 列表。每个观演人包含：
  - `identityId`
  - `realName`
  - `idCardNo`
- `order_item` 表增加：
  - `attendee_name`
  - `attendee_id_card`
- 下单时校验：
  - 所有身份证格式合法。
  - 如果传 `identityId`，必须属于当前用户。
  - 观演人总数必须等于订单总票数。
  - 不允许重复身份证。
  - 年龄必须满足 `ticket.age_limit`。

## 前端设计

- 客户个人中心增加“常用观演人”模块。
- 购票侧栏/详情页增加观演人选择区：
  - 按购票数量显示对应数量的选择位。
  - 可从常用观演人中选择。
  - 未维护证件时提示先添加。
  - 提交订单时携带每个票档对应的观演人列表。
- 后台票务创建/编辑页增加年龄限制选择，写入 `ageLimit`。

## 安卓设计

- 个人中心增加常用观演人入口。
- 结算页选择观演人。
- 安卓购物车/结算仍存在 mock，下单实名校验先以后端和 Web 客户端闭环为主，安卓随后对齐真实结算链路。

## 测试策略

- 后端单元测试：
  - 合法身份证通过。
  - 校验位错误失败。
  - 出生日期非法失败。
  - 年龄不足失败。
  - 票数和观演人数量不一致失败。
  - 重复身份证失败。
- 前端源码/工具测试：
  - 创建订单请求包含 `attendees`。
  - 购票页有观演人选择和年龄限制提示。
  - 票务创建/编辑页包含年龄限制字段。

## 范围控制

第一版只做中国大陆 18 位身份证，不支持护照、港澳台证件或儿童无证件购票。实名信息存储不做加密改造，只做展示脱敏，后续可单独规划敏感信息加密。
