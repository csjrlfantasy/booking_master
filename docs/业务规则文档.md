## 1. 订单状态机

### 1.1 状态定义

订单生命周期内包含以下7种状态：

| 状态名称 | 状态码 | 描述 | 可转换状态 |
|---------|--------|------|-----------|
| **待支付** | `PENDING_PAYMENT` | 订单已创建，等待用户支付 | 已支付、已取消 |
| **已支付** | `PAID` | 用户已完成支付，等待出票 | 已出票、退款中、已取消 |
| **已出票** | `TICKET_ISSUED` | 票品已生成（电子票/纸质票） | 已使用、已完成 |
| **已使用** | `USED` | 用户已使用票品（验票入场） | 已完成 |
| **已完成** | `COMPLETED` | 订单全部流程结束 | 终态 |
| **已取消** | `CANCELLED` | 订单被取消（超时/用户取消） | 终态 |
| **已退款** | `REFUNDED` | 退款成功，订单终止 | 终态 |

### 1.2 状态流转图

```
┌─────────────────────────────────────────────────────────────────────────┐
│                                                                         │
│     ┌──────────┐     支付成功     ┌──────────┐     出票成功    ┌───────┐│
│     │待支付    │ ──────────────→ │已支付    │ ────────────→ │已出票 ││
│     │PENDING_  │                │PAID      │                │TICKET_│
│     │PAYMENT   │                │          │                │ISSUED │
│     └──────────┘                └──────────┘                └───┬───┘│
│           │                          │                          │    │
│           │ 取消/超时                │ 申请退款                  │    │
│           ↓                          ↓                          ↓    │
│     ┌──────────┐              ┌──────────┐              ┌──────────┐  │
│     │已取消    │              │退款中    │              │已使用    │  │
│     │CANCELLED │              │REFUNDING │              │USED     │  │
│     └──────────┘              └────┬─────┘              └────┬────┘  │
│                                     │                         │       │
│                              退款成功                      完成     │
│                                     ↓                         ↓      │
│                               ┌──────────┐             ┌──────────┐  │
│                               │已退款    │             │已完成    │  │
│                               │REFUNDED  │             │COMPLETED │  │
│                               └──────────┘             └──────────┘  │
│                                                                         │
└─────────────────────────────────────────────────────────────────────────┘
```

### 1.3 状态转换规则

| 触发事件 | 转换路径 | 处理逻辑 |
|---------|---------|----------|
| 用户完成支付 | 待支付 → 已支付 | 校验支付结果，锁定库存，生成订单 |
| 支付超时 | 待支付 → 已取消 | 超过支付时限自动取消，释放库存 |
| 用户取消订单 | 待支付 → 已取消 | 用户主动取消，释放库存 |
| 系统出票 | 已支付 → 已出票 | 生成电子票/触发配送 |
| 验票入场 | 已出票 → 已使用 | 核验票码，标记使用 |
| 用户申请退款 | 已支付/已出票 → 退款中 | 进入退款审核流程 |
| 退款审核通过 | 退款中 → 已退款 | 原路返回支付金额 |
| 退款审核拒绝 | 退款中 → 已支付 | 恢复订单状态 |
| 订单完成 | 已使用 → 已完成 | 交易成功，触发评价 |

## 2. 退款规则

### 2.1 退款时效与退款比例

根据订单距离演出开始时间的长短，退款比例如下：

| 距离演出开始时间 | 退款比例 | 说明 |
|-----------------|---------|------|
| **≥7天** | 100% | 全额退款，不收取任何费用 |
| **3-7天（含7天）** | 70% | 退还70%票款，30%作为手续费 |
| **1-3天（含3天）** | 50% | 退还50%票款，50%作为手续费 |
| **<1天（24小时内）** | 0% | 不可退款，视为用户放弃 |
| **演出已开始** | 0% | 不可退款 |
| **演出已结束** | 0% | 不可退款 |

### 2.2 退款金额计算公式

```
退款金额 = 订单实付金额 × 退款比例
```

**示例**：
- 订单金额：200元，距离开演8天 → 退款200×100% = 200元
- 订单金额：200元，距离开演5天 → 退款200×70% = 140元
- 订单金额：200元，距离开演2天 → 退款200×50% = 100元

### 2.3 退款特殊规则

| 场景 | 处理方式 |
|------|----------|
| 订单使用优惠券 | 优惠券不退还，按比例分摊到每张票 |
| 部分退款 | 只退部分票品，剩余票品正常履约 |
| 多次退款 | 同一订单仅支持一次退款申请 |
| 退款到账时间 | 原路返回：微信/支付宝 1-3个工作日；银行卡 3-7个工作日 |
| 纸质票已寄出 | 退款需扣除快递费用，寄回票品 |

### 2.4 退款审核流程

```
用户申请退款
      ↓
提交退款申请（填写原因）
      ↓
系统自动计算退款金额
      ↓
客服/运营审核（人工/自动）
      ↓
┌────┴────┐
│  通过   │          │ 拒绝   │
└────┬────┘          └────┬────┘
     ↓                    ↓
执行退款           恢复订单状态
     ↓                    ↓
通知用户           通知用户拒绝原因
```

## 3. 支付规则

### 3.1 支付时效

| 票品类型 | 支付时限 | 说明 |
|---------|---------|------|
| **普通票** | 15分钟 | 普通演出、展览等票品 |
| **热门票** | 5分钟 | 热门赛事、秒杀等高竞争票品 |
| **定制票** | 30分钟 | 定制类票品（如企业团购） |

**说明**：支付时限从订单创建成功开始计时。

```

      │
      ▼
┌─────────────────┐
│  支付时限内完成 │─→ 正常出票
└────────┬────────┘
         │ 超时
         ▼
┌─────────────────┐
│  订单自动取消   │
│  释放库存       │
│  恢复优惠券     │
└────────┬────────┘
         │
         ▼
┌─────────────────┐
│  通知用户       │
│  （App推送/短信）│
└─────────────────┘
```

### 3.3 支付方式

| 支付方式 | 支持平台 | 到账时间 |
|---------|---------|----------|
| 微信支付 | App/Web | 即时 |

| Apple Pay | iOS App | 即时 |

### 3.4 支付安全规则

| 规则 | 说明 |
|------|------|
| 支付密码 | 单笔≥500元需验证支付密码 |

## 4. 库存规则

### 4.1 库存锁定机制（锁票）

用户选择座位并提交订单后，系统对该座位进行锁定：

| 阶段 | 锁定时间 | 释放条件 |
|------|---------|----------|
| 订单创建 | 支付时限内 | 支付成功/超时取消/用户取消 |
| 选座中 | 10分钟 | 超出时间未提交订单 |

### 4.2 超卖防护（乐观锁）

采用乐观锁机制防止超卖：

```
SQL: UPDATE ticket_stock SET quantity = quantity - 1, version = version + 1 
     WHERE ticket_id = ? AND quantity > 0 AND version = ?
```

**关键点**：
- 每条库存记录携带版本号（version）
- 更新时检查版本号是否一致
- 版本不一致说明存在并发冲突，触发重试机制
- 重试3次仍失败返回"库存不足"

### 4.3 限购规则

| 规则 | 限制值 | 说明 |
|------|--------|------|
| 单笔限购 | 10张 | 同一票品单次购买最多10张 |
| 每日限购 | 20张 | 单用户单日累计购买不超过20张 |
| 月度限购 | 50张 | 单用户单月累计购买不超过50张 |
| 身份证限购 | 1张 | 实名制票品每身份证限1张 |

### 4.4 库存预警

| 预警级别 | 库存余量 | 触发动作 |
|---------|---------|----------|
| 正常 | >20% | 正常销售 |
| 告警 | 10%-20% | 推送运营关注 |
| 紧缺 | 5%-10% | 显示"即将售罄" |
| 售罄 | <5%或=0 | 显示"已售罄" |

## 5. 优惠券规则

### 5.1 优惠券类型

| 类型 | 说明 | 使用条件 |
|------|------|----------|
| **满减券** | 订单满X元减Y元 | 订单金额≥门槛 |
| **折扣券** | 订单享受X折 | 无门槛/有门槛 |
| **立减券** | 直接减免固定金额 | 无门槛 |
| **品类券** | 指定票品类型可用 | 限制品类 |
| **新人券** | 新用户专属 | 仅首次下单 |

### 5.2 优惠券发放规则

| 渠道 | 数量限制 | 有效期 |
|------|---------|--------|
| 注册赠送 | 1张/用户 | 7天 |
| 活动发放 | 按活动规则 | 活动指定 |
| 积分兑换 | 100积分=1张 | 30天 |
| 人工发放 | 无限制 | 自定义 |

### 5.3 优惠券使用规则

| 规则 | 说明 |
|------|------|
| 叠加规则 | 优惠券与满减活动不可叠加，默认选最优 |
| 数量限制 | 单笔订单限用1张优惠券 |
| 使用门槛 | 满足门槛才能使用 |
| 找回规则 | 订单取消后，优惠券自动恢复 |
| 过期规则 | 过期未使用自动作废 |

### 5.4 优惠券分摊规则

多张票品订单使用优惠券时，按票价比例分摊：

```
单票优惠金额 = 优惠券总额 × (单票票价 / 订单总票价)
```

| 评价类型 | 触发条件 | 评价期限 |

| 匿名评价 | 用户选择 | 默认匿名 |

### 6.2 评价内容

| 评分维度 | 分值范围 | 权重 |
|---------|---------|------|

| 修改时限 | 评价发布后24小时内可修改 |
| 删除规则 | 评价不可删除 |
| 敏感词过滤 | 包含敏感词的评价不予显示 |
