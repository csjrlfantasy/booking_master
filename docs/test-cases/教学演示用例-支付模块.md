## 一、等价类划分法用例

### 1.1 分析对象：POST /api/payment/create 请求参数

**等价类分析表：**

| 字段 | 有效等价类 | 无效等价类 |
|------|-----------|-----------|
| orderNo | E1: 存在的待支付订单号 | E2: 空, E3: 不存在的订单号, E4: 非待支付状态的订单号 |
| amount | E5: 金额=订单payAmount | E6: 空, E7: 金额≠订单payAmount, E8: 金额≤0 |
| payChannel | E9: alipay, E10: wechat, E11: bank, E12: unionpay | E13: 空, E14: 不支持的值 |

## 二、边界值分析法用例

### 2.1 边界分析

| 边界来源 | 边界值 | 边界下方(min-1) | 边界值(min) | 边界上方(min+1) |
|----------|--------|-----------------|-------------|-----------------|
| 支付金额=订单金额 | 299.00 | 298.99 | 299.00 | 299.01 |
| 退款费率7天分界 | 距离演出168小时 | 167h59m | 168h | 168h01m |
| 退款费率3天分界 | 距离演出72小时 | 71h59m | 72h | 72h01m |
| 退款费率1天分界 | 距离演出24小时 | 23h59m | 24h | 24h01m |
| 支付超时15分钟 | 15分 | 14分59秒 | 15分00秒 | 15分01秒 |

## 四、状态转换法用例

### 4.1 支付状态转换图

```
                创建支付
                   ↓
           ┌──────────────┐
           │   PENDING    │──── 超时 ────→ CLOSED
           │   待支付      │
           └──────┬───────┘
                  │ mock-pay成功
                  ↓
           ┌──────────────┐
           │   SUCCESS    │──── 申请退款 ──→ 退款状态机 (REFUNDING→SUCCESS/FAILED)
           │   支付成功    │
           └──────────────┘
                  │ mock-pay失败
                  ↓
           ┌──────────────┐
           │   FAILED     │
           │   支付失败    │
           └──────────────┘
```

**合法转换：**
1. PENDING → SUCCESS（支付成功）
2. PENDING → FAILED（支付失败）
3. PENDING → CLOSED（超时关闭/用户取消）

**非法转换（应被阻止）：**
4. SUCCESS → PENDING（已支付退回到待支付）
5. CLOSED → SUCCESS（已关闭的支付被支付）
6. FAILED → SUCCESS（失败后直接变成成功）
