# M1 电商行业 —— 秒杀抢购模块

## M1.1 需求文档

### 功能概述

秒杀模块是电商平台的高并发核心功能，在指定时间段内以极低价格限量销售商品。

### 接口定义

| 接口 | 方法 | 认证 | 说明 |
|------|------|------|------|
| `/flash-sale/list` | GET | 无需 | 获取当前可参与的秒杀活动列表 |
| `/flash-sale/{activityId}/detail` | GET | 无需 | 查看秒杀活动详情（含倒计时、剩余库存） |
| `/flash-sale/{activityId}/order` | POST | 需要 | 发起秒杀下单 |
| `/flash-sale/{activityId}/pay` | POST | 需要 | 秒杀订单支付（15分钟内） |
| `/flash-sale/order/{orderId}` | GET | 需要 | 查询秒杀订单状态 |

### 业务规则

```
BR-FS-001: 秒杀时间窗口 [startTime, endTime]，不在窗口内不可下单
BR-FS-002: 每人每活动限购 1 件
BR-FS-003: 秒杀库存扣减使用 Redis 原子操作，库存=0 时返回"已抢光"
BR-FS-004: 下单后 15 分钟内必须支付，超时自动取消并回补库存
BR-FS-005: 秒杀价格独立于商品原价，活动期间以秒杀价为准
BR-FS-006: 秒杀商品不可使用优惠券
BR-FS-007: 支付成功后订单状态变更为 PAID，不可退款
BR-FS-008: 秒杀下单需通过滑块验证码
```

### 秒杀活动状态

| 状态码 | 含义 |
|--------|------|
| 0 | 未开始 |
| 1 | 进行中 |
| 2 | 已结束 |
| 3 | 已售罄 |

### 订单状态

| 状态码 | 含义 |
|--------|------|
| 1 | 待支付 |
| 2 | 已支付 |
| 3 | 已取消（超时/主动） |

### 核心数据模型

```
FlashSaleActivity:  activityId, goodsId, goodsName, originalPrice(原价),
                    flashPrice(秒杀价), totalStock(总库存), remainStock(剩余库存),
                    startTime, endTime, status(0/1/2/3), perLimit(每人限购,默认1)

FlashSaleOrder:     orderId, orderNo, userId, goodsId, activityId,
                    flashPrice, quantity, payAmount, orderStatus(1/2/3),
                    createTime, payTime, expireTime(创建时间+15分钟)
```

## M1.5 状态转换法

### 秒杀订单状态机

```
                    下单成功
                       │
                       ▼
                 ┌──────────┐
                 │ 1.待支付  │──── 超时15分钟 ──▶ 3.已取消
                 │          │    (回补库存)
                 └────┬─────┘
                      │ 支付成功(15分钟内)
                      ▼
                 ┌──────────┐
                 │ 2.已支付  │── 不可退款
                 │          │
                 └──────────┘


合法转换:
  1→2: 待支付→已支付（正常支付）
  1→3: 待支付→已取消（超时/用户取消）

非法转换:
  2→1: 已支付→待支付   ❌ 拒绝
  3→2: 已取消→已支付   ❌ 拒绝
  2→3: 已支付→已取消   ❌ 拒绝(秒杀不可退)
```

| 用例ID | 路径 | 预期 |
|--------|------|------|
| FS-FSM-001 | 1→2 (合法) | 支付成功，订单状态=2 |
| FS-FSM-002 | 1→3 (合法-超时) | 15分钟后自动取消，库存+1 |
| FS-FSM-003 | 1→3 (合法-主动取消) | 用户主动取消，库存+1 |
| FS-FSM-004 | 2→? (非法-申请退款) | code=100504 秒杀商品不可退款 |
| FS-FSM-005 | 3→2 (非法-对已取消订单支付) | code=100302 订单已取消 |

# M2 金融行业 —— 银行转账模块

## M2.1 需求文档

### 功能概述

银行转账模块处理个人账户之间的资金划转，支持同行和跨行转账，包含双因素认证。

### 接口定义

| 接口 | 方法 | 认证 | 说明 |
|------|------|------|------|
| `/transfer/create` | POST | Token+短信验证码 | 发起转账 |
| `/transfer/{transferId}/status` | GET | Token | 查询转账状态 |
| `/transfer/{transferId}/cancel` | PUT | Token+交易密码 | 撤销转账（仅处理中状态） |
| `/account/{accountNo}/balance` | GET | Token | 查询账户余额 |

### 业务规则

```
BR-TRANS-001: 转账金额: 单笔最低 0.01元，最高 50,000元；单日累计上限 200,000元
BR-TRANS-002: 转出账户余额 ≥ 转账金额 + 手续费
BR-TRANS-003: 手续费规则:
              - 同行转账: 免费
              - 跨行转账: 金额 ≤ 5000元 → 2元；5000-50000元 → 5元；>50000元 → 10元
              - 跨行加急(加急费): 额外 5元
BR-TRANS-004: 双因素认证: Token + 短信验证码（验证码5分钟有效，每日最多发送10次）
BR-TRANS-005: 收款账户必须存在且状态正常（不可为冻结/注销账户）
BR-TRANS-006: 转账金额超过 10,000元 需要输入交易密码再次确认
BR-TRANS-007: 当日 23:00 - 次日 01:00 为系统维护窗口，单笔限额降为 5,000元
BR-TRANS-008: 转账处理时间: 同行实时(秒级)，跨行普通(2小时内)，跨行加急(30分钟内)
```

### 转账状态

| 状态码 | 含义 |
|--------|------|
| 0 | 处理中 |
| 1 | 转账成功 |
| 2 | 转账失败 |
| 3 | 已撤销 |

### 手续费计算表

| 转账类型 | 金额范围 | 手续费 |
|----------|---------|--------|
| 同行 | 任意 | 0元 |
| 跨行普通 | ≤5000 | 2元 |
| 跨行普通 | 5000-50000 | 5元 |
| 跨行普通 | >50000 | 10元 |
| 跨行加急 | 任意 | 普通手续费+5元 |

## M2.5 状态转换法

### 转账状态机

```
      发起转账
         │
         ▼
   ┌──────────┐
   │ 0.处理中  │──── 撤销 ──▶ 3.已撤销
   │          │              (资金解冻)
   └────┬─────┘
        │
   ┌────┴────┐
   │         │
   ▼         ▼
┌──────┐  ┌──────┐
│1.成功 │  │2.失败│
│钱已到账│  │钱退回 │
└──────┘  └──────┘


合法转换:
  0→1: 处理中→成功（银行返回成功）
  0→2: 处理中→失败（余额不足/账户异常）
  0→3: 处理中→已撤销（用户主动撤销）

非法转换:
  1→0: 成功→处理中  ❌
  1→3: 成功→撤销    ❌ 钱已到账不能撤销
  2→1: 失败→成功    ❌
  3→1: 已撤销→成功  ❌
```

| 用例ID | 路径 | 预期 |
|--------|------|------|
| TRANS-FSM-001 | 0→1 | 合法：转账成功，两个账户余额正确变更 |
| TRANS-FSM-002 | 0→2 | 合法：转账失败，转出方资金解冻 |
| TRANS-FSM-003 | 0→3 | 合法：用户撤销，资金原路退回 |
| TRANS-FSM-004 | 1→3 | 非法：对已成功的转账申请撤销 → code=100501 |
| TRANS-FSM-005 | 3→1 | 非法：已撤销的转账重新成功 → 系统拦截 |

## M2.6 场景法

```
用户转账全流程（跨行加急）:

  基本流:
    登录→输入收款账号→填写金额(10000元)→选择"跨行加急"
    →系统计算手续费(10元)→获取短信验证码→输入验证码
    →金额>10000触发交易密码确认→输入交易密码→提交
    →转账处理中→30分钟内到账→状态变"成功"
```

| `/shipping/estimate-time` | POST | 无需 | 预估送达时间 |
| `/shipping/order/create` | POST | 需要 | 创建寄件订单 |

### 业务规则

```
BR-SHIP-001: 计费重量 = Max(实际重量, 体积重量)
              体积重量(kg) = 长(cm) × 宽(cm) × 高(cm) ÷ 6000
BR-SHIP-002: 首重 + 续重模式:
              - 首重 1kg: 固定首重费
              - 续重: 每增加 1kg(不足1kg按1kg算) 加收续重费
BR-SHIP-003: 区域划分:
              - 同城: 首重8元/续重2元/kg
              - 省内: 首重10元/续重3元/kg
              - 跨省邻近: 首重12元/续重5元/kg
              - 跨省远距离: 首重15元/续重8元/kg
              - 港澳台/国际: 首重30元/续重20元/kg
BR-SHIP-004: 快递类型:
              - 标准快递: 基准价
              - 特快加急: 基准价 × 1.5
              - 夜间配送(22:00-08:00): 额外加10元
BR-SHIP-005: 保价费 = 声明价值 × 0.5%(最低1元，最高50元)
BR-SHIP-006: 包裹限制:
              - 单件最重 50kg
              - 单件最长边 ≤ 150cm
              - 长+宽+高 ≤ 250cm
BR-SHIP-007: 重量≤3kg且尺寸在标准信封范围内的，按"文件/小件"计费(一口价):
              - 同城6元/省内8元/跨省12元
```

## M5.3 边界值分析

### 计费重量边界（体积重 vs 实际重）

```
体积重 = 长×宽×高 ÷ 6000

例: 50cm × 40cm × 30cm = 60000 ÷ 6000 = 10kg
    实际重量 9.99kg → 计费重 = 10kg (取体积重)
    实际重量 10.00kg → 计费重 = 10kg (相等)
    实际重量 10.01kg → 计费重 = 10.01kg (取实际重)
```

### 续重边界（不足1kg按1kg算）

| 用例ID | 计费重 | 续重部分 | 预期 |
|--------|--------|---------|------|
| SHIP-BV-001 | 1.00kg | 0kg → 续重=0 | 仅首重 |
| SHIP-BV-002 | 1.01kg | 0.01kg → 续重=1kg | 首重+1续重 |
| SHIP-BV-003 | 1.99kg | 0.99kg → 续重=1kg | 首重+1续重 |
| SHIP-BV-004 | 2.00kg | 1.00kg → 续重=1kg | 首重+1续重 |
| SHIP-BV-005 | 2.01kg | 1.01kg → 续重=2kg | 首重+2续重 |

## M5.5 场景法

```
用户寄快递全流程:

  基本流:
    输入寄件地址(北京朝阳区)→输入收件地址(广州天河区)
    →输入包裹信息(长50cm 宽40cm 高30cm 实重8kg)
    →系统计算: 体积重=50×40×30÷6000=10kg, 计费重=10kg
    →区域=跨省远距离, 首重15+续重8×9=87元
    →选择快递类型"标准"
    →选择保价(声明价值1000元, 保费=1000×0.5%=5元)
    →总费用=87+5=92元→创建订单

  异常流:
    E1: 包裹尺寸超标(最长边160cm)→提示"超出尺寸限制"
    E2: 包裹超重(55kg)→提示"单件不超过50kg，建议拆分为多件"
    E3: 夜间配送(23:00)→额外加10元
    E4: 地址无法识别→提示"请检查地址"
```
